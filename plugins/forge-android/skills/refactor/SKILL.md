# Android 重构

改善现有代码的维护成本，不以文件变多、类变小、模式变复杂证明成功。项目规则决定模块、命令、兼容范围和验收场景；本技能不预设具体架构。

## 先确认目标与边界

从用户请求、已有方案和当前改动中确认要改善什么、做到哪里算完成。信息够用就直接推进，不把整理背景变成固定审批环节。

区分两种任务：

- **结构整理**：默认保持公开接口和可观察行为，只调整实现组织。
- **目标驱动改造**：逐项区分必须保留的契约、明确批准的变化、尚待调查的行为。已确认要修正的旧缺陷不应被永久冻结；没有依据的变化不能借重构带入。

用接入步骤减少、决策归属清楚、同类修改集中或重复规则消除等具体结果表达目标，不用“更优雅”或机械行数阈值替代完成标准。

局部整理可简短说明后直接实施；涉及公共契约、跨模块迁移、持久化或执行时序时，先给出受影响边界、迁移顺序和验证方式。遵循用户已有审批要求，不重复索取已经给出的授权。

## 调查实际实现，不从类名推断

1. 确认任务所属工作区、现有改动及项目规则，保护用户未提交内容。不从哪个 worktree 有改动猜任务位置。
2. 阅读目标完整实现、相关测试及真实消费者。按需追踪初始化、注册、调用、状态恢复和清理路径，不能只看待整理的类。
3. 符号关系优先使用可用的 IDE 索引；连接失败、空结果或指向其他项目时退回文本搜索，并说明限制。
4. 区分代码实际行为、文档承诺和推测。测试若固化了已批准修改的旧行为，应解释并更新，不能为了通过测试撤销需求。

已有任务基线仍有效时复用，不为每批重新扫描完整历史和全部仓库。

## 选择需要保护的语义

只检查与改动相关的风险，不要求每项任务遍历完整清单：

| 改动涉及 | 应核对的边界 |
|---|---|
| 方法、类型和调用迁移 | 接口、空值、错误、默认值、副作用及未迁移消费者 |
| 对象、任务和回调组织 | 创建与读取时点、惰性/即时求值、实例身份、执行代次、重复或迟到回调、取消及终态 |
| 颜色、布局等资源 | 精确值、构造参数覆盖、资源限定符、渠道/模块同名覆盖、selector 状态与解析时机 |
| 缓存、存储及历史恢复 | 空间归属、旧数据兼容、清理生命周期和恢复语义 |

把逐项创建改为预先构造集合、缓存原查询、合并近似颜色、移动资源解析时点，都可能改变行为，不能只按语法等价判断。

保持已存在的资源差异，除非明确批准视觉收敛；保持已存在的状态隔离，除非明确批准新的状态契约。

## 用最少结构完成迁移

- 优先删除冗余、改名、内联不必要包装、收拢同一决策；只有职责独立或确实复用时才抽取。新增抽象或修改接口要有实际消费者与目标收益的证据；信息不足先调查，不凭空补可选 API 或兼容层。新结构必须比旧结构更容易理解或接入。
- 不为每个使用点生成一对一别名，不为测试暴露内部入口，不为套设计模式增加层级。
- 根据依赖决定顺序，不机械要求接口先行或一次替换所有调用方。必要的过渡入口有明确消费者和退出条件，不为假想兼容保留无用包装。
- 按完整职责或可验证调用链组织批次，不按方法数、文件数机械切分；批内小步编辑，批次结束检查集成行为。不要求每改一行就完整构建或停下来汇报。
- 如果证据显示方案没有降低复杂度，收缩或调整方案，不靠追加抽象修补。发现新的行为变化或范围扩大时先说明，不悄悄纳入本批。

## 验证目标与行为

先建立能够覆盖当前风险的基线，再验证迁移；优先利用已有公开入口和测试。

- 缺少自动覆盖时，补最小行为测试、快照或定向集成验证。测试不应复刻生产算法或仅断言新类、新资源存在。
- Android 资源的宿主侧精确值/覆盖检查不能证明真实资源解析与视觉等价；状态模型测试不能证明 Android 生命周期、线程或 native 集成正确。
- 按项目实际命令执行最小相关测试与编译。已存在失败需与本次新增失败区分，不用跳过检查掩盖问题。
- 资源、布局、持久化、线程与设备行为的风险无法由编译覆盖时，列出必要的集成/设备验收；未执行就明确保留缺口，不谎称完整通过。
- 除测试结果，还核对维护目标：调用方是否真正简化、决策是否唯一归属、新增同类能力是否减少修改点。

没有测试并不意味着可以凭直觉宣称行为等价；也不为维持“纯单测”而制造生产抽象。无法建立足够证据时，缩小改动或明确暂停的风险边界。

## 收尾和授权

确认调用方、资源引用及必要的反射/配置入口已迁移后，才清理旧实现；不能仅凭文本零引用断言没有消费者。同步受影响的测试和现有文档，不默认创建新的长篇设计文档。

重构授权不包含提交、推送、安装、发布、删除用户数据或覆盖未提交工作。设备操作遵循当前绑定和项目流程；环境、签名或冲突问题不能通过复制凭据、换机或丢弃工作绕过。

交付简述结构改善、保留与批准改变的行为、实际执行的验证以及未验证部分。完成标准未满足时说明剩余范围，不以“编译通过”替代验收。
