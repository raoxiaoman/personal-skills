# Android 开发

以项目实际代码、规则和验证入口为依据。小改动直接推进，不为普通修改生成完整架构方案，也不把项目专属命令、包名或设备写成通用事实。

## 确认任务与分流

确认任务所属工作区、现有改动与项目规则；按任务上下文定位，不从哪个 worktree 有修改来猜目标。仅在需要执行构建或设备操作时确认对应模块、variant、applicationId 和实际命令。

| 任务 | 执行方式 |
|---|---|
| 日常功能修改、局部 Bug 或构建问题 | 使用本流程；先确认根因或需求边界，再做最小修改 |
| 整理职责、简化框架、资源治理或迁移调用方 | 加载本包 `forge-android:refactor`；跨 Agent 时直接读取相邻 `../refactor/SKILL.md` |
| Java → Kotlin 迁移 | 加载本包 `forge-android:migrate-kotlin`；跨 Agent 时读取 `../migrate-kotlin/SKILL.md` |
| 平板、大屏与折叠屏适配 | 加载本包 `forge-android:adapt-large-screen`；跨 Agent 时读取 `../adapt-large-screen/SKILL.md` |
| 日志添加、后台采集或临时日志清理 | 加载本包 `forge-android:logging`；跨 Agent 时读取 `../logging/SKILL.md` |
| 编写或执行 Maestro 设备回归 | 加载本包 `forge-android:maestro`；跨 Agent 时读取 `../maestro/SKILL.md` |
| 发版前检查和证据核对 | 加载本包 `forge-android:check-release`；跨 Agent 时读取 `../check-release/SKILL.md` |
| 新旧 APK 包体变化及增长归因 | 加载本包 `forge-android:analyze-apk-size`；跨 Agent 时读取 `../analyze-apk-size/SKILL.md` |
| 根据 Figma/截图实现页面或校准视觉差异 | 加载本包 `forge-android:implement-ui`；跨 Agent 时读取 `../implement-ui/SKILL.md` |
| 添加、审查或验证业务 Analytics 埋点 | 加载本包 `forge-android:analytics`；跨 Agent 时读取 `../analytics/SKILL.md` |
| GPU、Shader、封面模板等独立专项 | 使用实际可用的对应专项技能，不在本流程重复实现 |

各入口均可独立调用；专项已接管时不绕回本入口，只补缺少的通用检查，不重复调查和验证。工具未安装或必要条件不满足时说明具体缺口，不假称已执行；J2K 的工具缺口不能用手写转换绕过。未迁入的外部独立专项按实际可用入口处理。

## 阅读真实实现后修改

- 阅读目标完整方法或类、紧密相关测试和真实调用点；遇到时序、状态、恢复或清理问题时再沿调用链扩大范围，不默认扫描全部历史。
- 符号关系优先使用指向当前项目的 IDE 索引；连接失败、空结果或路径属于其他项目时退回文本搜索，说明限制，不反复重试。
- 区分实际行为、需求和推测。Bug 先定位原因；新行为确认验收标准；纯整理不顺手改变默认值、接口或业务规则。
- 小步完成有独立职责的改动。优先清晰命名、提前返回和删除冗余；不为缩短方法机械增加包装、层级或测试专用入口。
- 对项目列出的热点文件遵循其职责与验证要求。未列热点不代表没有风险，仍按真实调用链判断影响。

## 布局与生命周期

布局容器按实际测量、定位、复用和交互需求选择，不强制所有根布局改为 `ConstraintLayout`。删除嵌套前检查布局参数、尺寸测量、显隐、触摸分发、无障碍、背景/裁剪、动画和 ViewBinding 引用；“只改容器”也可能改变行为。

保护手机基线、资源限定符和已有复用边界。不在普通修复中顺手拍扁整页或改变 UX；页面结构变化需要真实界面验证，编译通过不能证明视觉与交互等价。

组件修改按涉及范围检查 View 生命周期、异步回调、取消与释放、状态恢复和重复点击；不把所有检查机械套到每个局部改动。

## 选择能覆盖风险的验证

| 改动 | 验证依据 |
|---|---|
| Java 或 Kotlin 实现 | 项目对应语言的编译检查，以及受影响行为测试 |
| 混合语言或跨模块接口 | 覆盖双方调用与类型契约，不仅编译单侧 |
| 资源、Manifest、Gradle、variant、生成代码 | 项目对应模块/变体的资源链接、构建或集成检查 |
| 状态、线程、持久化、布局与设备行为 | 增加覆盖实际风险的集成或设备验收；缺口明确报告 |

项目未提供命令时，从实际构建配置、现有脚本与 Gradle task 确认，不猜 `:app` 或 `installDebug`。先利用已有公开测试入口；不反射调用私有业务方法、不复制生产算法作为断言，不为测试改造简单生产结构。

区分原有失败和新增失败。需要的验证超出当前授权或环境能力时报告缺口，不通过跳过检查、复制签名配置或切换设备绕过。

## 设备与操作授权

只有明确获得安装或启动授权才执行。操作前核对当前 `ANDROID_SERIAL` 及该绑定设备的可用性；不沿用历史序列号、不自动换机。未绑定或不可用时停止设备操作并确认目标，Gradle 和 adb 使用同一绑定。启动方式按项目实际入口执行，不强制覆盖项目流程。

重构、修复或“继续”不隐含提交、推送、发布、删除用户数据或覆盖未提交工作。遵循现有 Git/提交流程，不维护第二套自动提交状态机。日志采集不扩大安装、启动或数据清理授权。

交付说明实际改动、验证命令与结果，以及未验证部分。发现范围扩大或行为变化时及时说明，不以编译成功代替功能验收。
