# 大屏与折叠屏适配

可直接使用本专项。项目规则决定窗口 API、模块与验证命令；适配规模由实际页面和验收范围决定，不预设整应用改造。

## 固定范围和基线

1. 确认 UI 技术栈、SDK、当前窗口 API、屏幕/平板判断和已有资源限定符。先读目标实际实现、相关测试和手机分支；存在历史回归或默认值疑问时再定向查历史，不扫描所有关联项目。
2. 明确本次窗口与页面：手机、折叠闭合/展开、平板及其方向，列出未纳入范围。分屏、自由窗口拖动和连续缩放仅在明确要求时扩展，不顺便迁移 Target SDK 或返回框架。
3. 沿宿主、Fragment、Pager/Adapter 到实际列表和绘制叶子页面，核对弹窗、面板与返回入口。局部页面无需完整全应用映射；多页面任务使用 [页面与验收清单](references/checklist.md)。
4. 记录手机现有列数、item 尺寸、padding/间距、点击边界、滚动/动画位移、Tab 和 inset。以设计或截图定义大屏目标；没有设计时说明假设，不擅自做 UX 重排。

## 从可用窗口推导参数

- 使用项目已有的 WindowMetrics、实际内容容器尺寸或等价 API；设备 `isTablet` 与物理屏幕宽度不能代表当前窗口。窗口 bounds、系统 inset 和内容 padding 不能重复扣除，dp/px 与密度转换要一致。
- 优先在真实布局完成后根据可用内容宽高计算。无效/零尺寸等到布局就绪，不拿全屏缓存值冒充当前内容尺寸。
- 核对 `static`/companion、Singleton 和 Adapter 是否缓存旧窗口参数；只在实际尺寸/配置变化时重算，防止递归布局刷新和重复监听。
- 把同一套重复参数计算放在合适的现有入口；只有确有职责或复用时才新建 Helper。不为测试引入统一 God Resolver，也不要求所有页面共用同一个公式。
- 保留手机分支；仅在目标窗口条件满足时应用新参数。不要从大屏值反推旧手机默认值，也不通过复制整套 XML 制造两套易漂移实现。结构确实不同且收益明确时可使用限定布局。

## 根据组件语义改造

- 网格由可用内容宽度、最小 item 宽度、间距和比例决定。先满足可读性和触控目标，再选择列数；间距不默认随屏幕无限放大。固定列数必须有明确设计与适用窗口范围。
- 列数变化不必一律重建 LayoutManager；选择最小更新方式，保护滚动锚点、选中项、分页与嵌套横向列表状态。尺寸变化也要更新卡片与动态封面。
- Tab 根据数量、动态文案、多语言、可用宽度选择 fixed/fill 或 scrollable；不把所有分类均分，也不机械统一宽度。
- Dialog/Popup/BottomSheet 根据窗口和 inset 设置内容宽度/最大宽度，旋转后重新计算；区分容器全宽与内容可读宽度。
- 编辑页先检查工具密度、点击边界和浮层，再调整预览与操作区分配。涉及时间轴/面板时梳理组合状态，不用一个固定高度特判掩盖整体布局问题。
- 不为适配顺手更换所有布局容器。保留测量、触摸、显隐、裁剪、无障碍和 Binding 语义；资源 qualifier/flavor 的覆盖关系同样要核对。

## 更新与恢复

核对宿主如何把窗口变化传给实际承载页面，复用项目机制，不强制新增递归分发框架。View 尚未创建时保留可重新取得的最新尺寸，在初始化后应用；监听随 View 生命周期解除，避免旧回调更新重建后的页面。配置重建、旋转、恢复和返回后重新进入不能继续使用旧缓存。

## 验证与交付

- 先运行当前语言、资源或依赖变化对应的项目最小编译/测试，不猜模块或固定 assemble 命令。
- 默认/手机路径和目标大屏路径都要验证；按本次范围检查旋转、滚动末尾点击、弹窗、返回、长文案和空/加载/错误/权限状态。截图要记录设备、窗口、方向和密度，不能仅比较像素大小。
- 涉及布局与交互时执行获得授权的设备/模拟器走查。安装启动仍需独立授权，使用当前绑定设备；缺少手机/大屏设备或界面验证条件就明确验收缺口，不把静态公式测试或编译当适配完成。
- 系统返回/预测性返回仅在任务明确涉及且核对 SDK/API 后处理；不要把旧版本经验写成所有设备通用规则。

交付列出实际页面、保持的手机行为、目标变化、验证证据和未覆盖范围。实现授权不包含提交、推送、安装、发布或用户数据清理。
