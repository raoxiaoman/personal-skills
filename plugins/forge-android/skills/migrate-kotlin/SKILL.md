# Java → Kotlin 迁移

可以直接执行本专项，不必先调用 develop。项目规则决定模块、变体、基类、代码风格和验证入口；本技能不假定具体项目 API。

## 确认迁移边界

1. 确认任务工作区及已有改动，完整阅读目标 Java 类、直接父类、相关布局、实际消费者和已有测试。保护工作区内容，不用 HEAD 版本覆盖。
2. 找到同类 Kotlin 页面惯例。只有任务需要时才替换基类、引入 ViewBinding、迁移监听或工具调用；语言转换不是自动重写页面的授权。
3. 根据实际代码记录必须保持的创建与回调顺序、参数默认值、返回协议、生命周期注册清理、窗口与 inset 行为。跨语言、反射、XML 和配置中的调用同样是消费者。
4. 若替换基类或 ViewBinding，按 [UI 与兼容检查](references/ui-compatibility.md) 核对适用部分，不机械执行所有现代化操作。

## 官方 J2K 是转换前置条件

- 使用当前会话实际可用的 Android Studio 官方 J2K 接口；已配置 IDE MCP 时确认工具可用、项目路径与索引归属正确。若提供 `ide_convert_java_to_kotlin`，按它的实际 schema 传入路径，不臆测参数或返回字段。
- MCP 连接失败、指向其他项目、J2K 写工具缺失或转换失败时，**停止语言转换**，说明具体阻塞。文本搜索只能替代符号检索，不能替代 J2K；不静默手写 Kotlin，不用 Accessibility 自动点菜单，也不擅自启动/重配 IDE。
- 用户明确选择在 IDE 中手动运行官方 J2K 时，待转换结果实际落盘后再继续整理；不能把用户同意排障解释成同意手工重写。
- 逐文件确认官方转换成功、包名与类名保持、Java 已被 Kotlin 替换、原工作区改动仍在。同步目标目录或新旧两个文件，避免残留 Java PSI 造成重复符号。
- 读取真实 J2K 产物后再整理；不要按预想结果提前生成替代文件。

## 有边界地整理产物

- 优先清除冗余强转、泛型和全限定名，使用项目一致的 Kotlin 表达。属性、safe call、Elvis、Lambda、集合操作只有在求值顺序、副作用和空值契约等价时才替换。
- 不将原允许为空的值改成无条件 `!!` 或 `lateinit`，不通过默认空串/零值吞掉原错误。不要用 `runCatching` 等包装暗改异常传播或取消行为。
- 不因“更 Kotlin”改变线程、惰性/即时求值、回调次数、监听共享、集合可变性或对象身份。额外结构治理交给 refactor 的流程，但不重复调查。
- 使用项目既有且语义等价的扩展函数；确认 FragmentManager、状态丢失、异常和返回语义，不为单次替换创建新包装。
- 点击改为 Lambda 时保留项目防重复点击和控件语义。动态共享监听有实际职责时可以保留接口与分发，不机械逐个生成监听对象。
- 按 XML 与 Java 消费者保留构造函数、静态入口和 JVM getter/setter。是否需要 `@JvmOverloads`、`@JvmStatic` 或 keep 规则取决于真实调用，不批量添加。

## 验证与停止

1. 运行可用的 IDE 同步与 diagnostics，核实 ERROR 的来源。官方转换完成后 diagnostics 暂不可用时，记录编辑器检查缺口，不伪造通过；疑似 stale PSI 先同步核查，不能为消除 IDE 假报改业务代码。
2. 运行项目对应 Kotlin 编译和受影响测试；有 Java 消费者、构造函数或跨语言 API 时同时覆盖 Java 编译。资源、生成 Binding 或 Gradle 变化需要对应资源链接/变体构建，不猜模块名。
3. 检查原公开入口、布局引用、ButterKnife 与旧字段残留。残留逐项判定，不靠全局正则删除，也不因“未使用”警告移除反射/XML API。
4. UI、生命周期、窗口和混淆风险列入相应集成/设备或 release 验证；编译不证明交互、inset、恢复或反射动画等价。安装启动需单独授权并遵循当前设备绑定。
5. 查看忽略行尾的真实 diff；不为 `diff --check` 误报归一历史 CRLF。不自动提交、推送或安装。

J2K 不能执行、基类行为不明、业务语义冲突、启用 ViewBinding 会超出已同意范围，或验证受环境/签名/无关失败阻塞时，停下受影响步骤并报告。交付说明实际转换方式、额外接入改动、保留的兼容性、执行过的验证和未验证范围。
