# Android UI 实现与校准

先确认设计目标、真实页面与授权，复用现有技术栈和组件。已有明确修改要求就继续实现，不再以默认 confirm 模式重复等待；仅比较时不改代码。

## 输入与定位

1. 读取目标项目规则、现有改动和页面入口，确认 Compose、XML 或混合结构。按指定 screen/route/Activity 找到真实承载页面，不从目录名猜测。
2. Figma 输入按当前服务要求加载前置技能、创建文件会话，再读取目标节点的设计上下文和截图。链接缺节点时先核对可用结构，仍有多个目标才询问；访问失败不编造设计数据。
3. 已提供截图或视觉要求时不强求 Figma 链接。记录可确定的尺寸、状态和不确定项；截图像素不足以证明 dp、字体或资源 token。
4. 仅需读取设计时不写 Figma，不用 `use_figma` 绕过上下文读取，不上传设备截图；Figma 修改或上传须另有明确请求。

## 实现

- 先读 [布局与组件](references/layout.md)，复用项目颜色、字体、主题、间距和组件；不因为参考代码用了另一框架就迁移 Compose/XML。
- 结合设计基准、可用窗口、density、fontScale 和 Insets 推导尺寸，不把 Figma px 或截图像素机械当 dp/sp。
- 默认修改目标页面、UI 资源与必要交互接线，保护现有状态、回调、Binding、可访问性和手机基线。需要改变业务规则、导航契约、持久化或项目配置时先说明范围，不为视觉修正顺手重构底层。
- 只有大屏/折叠窗口适配才按需使用 `forge-android:adapt-large-screen`；诊断日志使用 `forge-android:logging`。专项接管不重复调查。

## 验证与设备证据

按项目实际模块和 variant 做最小编译/资源验证。安装、启动分别需要有效授权；使用项目已有命令，不默认 `:app:installDebug`，不为每次静态比较都构建安装。

设备仅使用当前 `ANDROID_SERIAL`，显式参数冲突或设备不可用时停止，不列设备选机、不自动启动 AVD。页面操作优先项目 Maestro flow；截图不授权导航、安装、启动或清数据。

本技能只提供 [截图工具](scripts/capture_ui.py)，不实现第二套构建/安装流程或 YAML 配置系统：

```bash
python3 -I -B "<技能目录>/scripts/capture_ui.py" \
  --output-dir "<项目和插件之外的全新证据目录>" --layout-tree
```

`--layout-tree` 可省略；`--serial` 只能匹配当前绑定，`--adb` 可指定已安装的可执行文件。输出含 `screen.png`、`device.json`，请求层级时另有 `layout.xml`。已有目录拒绝覆盖；失败保留已采集证据并非零退出。截图可能含个人内容，先确认页面安全，不自动上传。

## 比较与交付

按 [视觉核对](references/comparison.md) 比较整体尺寸、Insets、布局、文字、样式和内容状态。布局树辅助定位，不把缺少 Compose 语义节点认定为元素不存在。

每轮针对有证据的差异修改，再按授权获得新截图；没有新产物不能拿旧包截图冒充修改后结果。不设机械轮数或像素分数作为通过门槛；构建/采集失败、目标不明、无实际改善或权限不足时报告具体缺口。

交付代码位置、已修差异、实际验证及产物路径。编译、Preview、截图存在与真实视觉/交互通过分开；没有设备验证就明确未验证。不自动提交、发布、修改设备全局设置或清理用户数据。
