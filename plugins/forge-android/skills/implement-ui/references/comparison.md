# 视觉核对

## 比较口径

先确认参考节点/截图、应用版本、实际页面和内容状态。记录窗口尺寸、density、fontScale、方向、主题、语言及系统栏；没有观测到的环境标未知，不从设备型号猜默认值。

1. 比较画板与实际可用窗口，明确是否包含系统栏、键盘和遮罩。
2. 比较主容器边界、对齐、滚动与 Insets。
3. 比较控件尺寸、间距、点击区域和布局状态。
4. 比较字体、字重、行高、基线、换行和截断。
5. 比较颜色、透明度、圆角、边框、阴影及图片裁剪。
6. 核对目标状态下的交互与可访问性；必要时覆盖加载、空态、长文本或键盘。

不要把像素 diff 当唯一结论，也不凭肉眼给出未测量的精确误差。比例调整应来自设计基准，不为掩盖错位任意拉伸参考图。

## 辅助证据

Figma 生成代码是适配参考，不是可直接覆盖项目的最终实现。先复用项目组件、资源和约束，再选择必要的几何与样式信息。

Android 层级可辅助核对文本和 bounds，但可能缺少自绘内容、合并的 Compose 语义或遮挡后的节点。层级缺失不能证明未绘制，节点存在也不能证明可见、命中或视觉正确。

截图可能包含账号、头像、聊天或输入内容；限定在已确认安全的测试页面，仅保存在本轮本地专属目录，不默认发送到 Figma、图床或其他服务。

## 结论

按影响说明结构/核心内容错误、明显布局差异、局部样式差异和环境/渲染不确定项，不强制所有细微差异都修正。每项关联观察位置、原因证据和对应代码；没有来源的设计值标待确认。

新截图必须对应本次验证的包、页面和状态。仅编译或 Preview 时写明该层级；没有真实视觉证据就保留缺口，不把“文件已生成”或“命令退出 0”改写成用户验收通过。
