# 布局与组件

## 定位真实承载

Compose 从 `setContent`、目标 Composable、状态持有者和导航参数确认入口；XML 从 Fragment/Activity、layout、include/merge、Binding 和资源限定符确认。项目混合使用时保持现有边界，不引入另一套实现。

先核对页面的加载、空、错误、已选中、禁用等需求状态。保持可见内容、账号状态、语言与设计参考的比较口径一致，不为得到“漂亮截图”改变业务状态机。

## 尺寸与主题

- 确认设计画板的参考宽高与缩放关系；Android 实际窗口、density、fontScale、系统栏和软键盘均会影响结果。
- 使用当前主题、日夜资源、Typography、字体、颜色和组件样式。设计值与项目 token 冲突时说明影响，不静默改全局 token。
- 检查触控区域、文本截断、字体回退、对比度、contentDescription、焦点和可访问性，不以静态外观牺牲交互。
- 文字字号、行高、字距和基线分别核对，不仅比较文本外框；字体抗锯齿不能用随意缩放去抵消。

## Compose

保护状态提升、remember 的 key、回调和重组语义；样式调整不顺手改变状态归属。按项目写法处理 `WindowInsets`、滚动、语义与动态内容。

已有 Preview 可用于固定状态的初步核对；Preview 不是实际窗口、设备字体、键盘或导航行为的证据。

## XML/View

检查约束、权重、wrap_content、最小尺寸、触摸分发、裁剪和显隐；不强制根布局类型或为减少层级拍扁页面。保护 include/merge、ViewStub、Binding、监听器和主题属性。

Window/Manifest、资源限定符或公共组件修改可能影响其他页面，按实际影响验证，不因文件看起来是 UI 就视为局部无风险。

## 验证

Java/Kotlin 使用项目对应编译与受影响测试；资源和布局用实际资源链接/构建入口；必要时覆盖双方调用。安装、启动后，通过已授权的页面操作核对目标状态，再采集新证据，不能用旧包或错误页面替代。
