## 一、环境与前置

- 其他前置：（网络、开发者选项、折叠态）

### 设备矩阵

**换设备后核对设备契约**（见 `../references/device-portability.md`，`device_info` 可输出快照）；执行仅使用当前 `ANDROID_SERIAL`。

| 设备 | 型号 / ROM | SDK | 系统语言 | 尺寸 / 密度 | fixture 已投放 | 本组场景已验证 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

三个必须记录的字段，缺一个都可能让脚本在另一台设备上失败：

- **系统语言** —— 决定文本选择器是否成立（实测三台设备分别为 `zh-CN` / `en-AT` / `zh-Hans-CN`）
- **尺寸 / 密度** —— 决定百分比点击和 `visibilityPercentage` 是否够用
- **fixture 已投放** —— 不投放的话脚本在第一步就失败，且失败信息与产品无关

## 二、场景矩阵

| 编号 | 场景 | 前置 | 自动化能力 | 证据方式 | 跨设备 |
|---|---|---|---|---|---|
| XXX-01 |  |  | 可自动 / 需编排 / 人工 | 断言 / 截图 | 通用 / 设备限定 |

「自动化能力」三档：

- **可自动** —— 一条 `maestro test` 跑完
- **需编排** —— 需要 shell 配合（跨调用时间窗、已授权的设备状态切换或专属测试数据准备），并写明理由及副作用
- **人工** —— 说明为什么无法自动化（断言不到、需要人判断、无法构造）

「跨设备」两档：

- **契约内通用** —— 声明所支持的语言、屏幕/窗口、ROM；设计可移植与实际验证矩阵分别记录
- **设备限定** —— 写明限定条件（哪台设备 / 哪个 ROM / 哪个折叠态），以及其它设备上跳过还是人工

每个场景按下述结构写。**「已知边界」不能省** —— 它决定了这个场景通过意味着什么。

### XXX-01 <场景名>

**前置条件**

- ...

**步骤**

1. ...

**预期结果**

- ...

**自动化能力**：可自动 / 需编排 / 人工
**对应脚本**：`maestro/<功能>/<场景>.yaml`
**证据方式**：断言 / 截图人工判断（写明人工要看什么）

**已知边界**

- 本场景不覆盖的分支，以及原因（例如「Cancel 分支与 XXX-02 行为完全一致，不重复覆盖」）
- 脆弱点（例如「关闭广告靠坐标点击，SDK 换位置就会点空，失败时先手工截图确认位置」）

**清理动作**

- 本场景产生的草稿 / 文件 / 状态变更，怎么恢复
