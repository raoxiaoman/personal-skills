# 验证与自检

## 隔离检查

`maestro check-syntax <flow>` 检查 YAML 和命令结构，`bash -n <script>` 检查 shell 语法；两者不验证运行时状态、参数传递或业务语义。使用当前工具版本确认命令可用，不把历史静态通过当本轮证据。

桩测试隔离外部命令，不连接设备。下面只演示接口组合；真实状态、异常路径和退出码应使用自动断言，而非仅看打印：

```bash
set -euo pipefail
source ./lib-device.sh

export ANDROID_SERIAL=SER1
adb() {
  [[ "$*" == '-s SER1 get-state' ]] || return 1
  printf 'device\n'
}
device_wifi_state() { printf '0\n'; }
device_wifi() { printf '恢复 %s 为 %s\n' "$1" "$2"; }
maestro() { printf '%s\n' "$@"; }

( restore_wifi_on_exit "$ANDROID_SERIAL"; printf '正文完成\n' )
maestro_phase "$ANDROID_SERIAL" "/abs/path with spaces/flow.yaml" "arm" -e A=1 -e B=2
```

重点覆盖：

- 未绑定、显式 serial 冲突和 `get-state` 不可用时，在操作前失败；不执行设备枚举。
- Wi-Fi 初始开/关均恢复原值；正常退出、原业务失败和恢复失败的退出码均正确。
- 已有 EXIT trap 时不覆盖；多个清理动作显式组合，某项失败不能阻止其余必要恢复。
- 切换命令失败、回读未知或状态不符不会继续业务步骤；不会修改蜂窝网络。
- dump 失败不读取旧结果，本次路径独立；屏幕正常 Physical/Override、方形和歧义输出均正确处理。
- flow 路径带空格、参数含特殊字符、PHASE 和 `-e` 原样透传；漏参可明确失败。
- `set -e` 的条件调用、管道和子 shell 例外不吞关键错误。

桩测试只证明宿主脚本行为，不代表真实 Android 命令、Maestro flow 或设备状态已验证。

## 授权后的设备执行

先核对当前 `ANDROID_SERIAL` 的可用性，再准备前置并逐场景执行。Maestro 与 ADB 使用同一绑定，不依据唯一在线设备推断目标；同设备串行，不擅自终止其他会话进程。

每个场景先确认账号、权益、素材、页面状态和入口就绪。失败后检查是否污染后续前置；改过状态就回读恢复。已有验收标准直接采用，不重复要求用户批准同一覆盖范围；新增副作用仍须独立授权。

按实际风险选择设备矩阵：语言、屏幕/窗口、折叠态、SDK、ROM、动画和性能可能改变结果。仅单机验证时明确该范围，不能称跨设备通过；设备数量本身也不替代有针对性的覆盖。

## 结果分级

| 结果 | 证据边界 |
|---|---|
| 自动断言通过 | 当前设备、输入与前置下，已覆盖的观察结果符合预期 |
| 截图人工通过 | 明确由谁核对、核对了什么；截图存在本身不证明正确 |
| 失败 | 区分已证实的产品缺陷、脚本失败与前置不满足 |
| 无法执行 | 记录环境、账号、服务端或授权缺口，不转成通过 |

页面未跳转必须结合入口就绪、点击命中、观察窗和状态变化判断；不能单独排除点击未响应。退出 0 不代表音质、视觉、服务端接收或完整业务验收。

## 收尾清单

- 场景说明、flow、参数和实际覆盖一致；未自动化项及原因明确。
- 循环有上界，连接点有就绪护栏，关键结论排除旧结果或互斥状态。
- 已记录设备、工具版本、fixture 和产物路径，原始失败证据保留。
- 本轮改变的 Wi-Fi、开发者选项等状态按原值恢复并回读；恢复失败明确报告。
- 只按授权清理本轮专属测试产物，不清登录态、用户草稿或其他功能目录。
- 临时日志按日志规范清理；长跑期间不改脚本或输入表，变更后重新固定输入和运行。
