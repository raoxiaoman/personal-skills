# Maestro 能力边界与陷阱

下列历史观察来自 Maestro 2.10.0 的 Android 环境；当前版本、系统、控件实现或平台变化后按风险复验。它们帮助定位问题，不是全部版本或 iOS 的能力保证。

## 等待与时间窗

历史环境中 `Java.type('java.lang.Thread').sleep(...)` 抛出 `TypeError: Cannot read property 'type' of undefined`，说明该路径没有 JVM 互操作，不说明 Maestro 没有任何等待能力。

页面加载、结果出现和动画优先使用当前版本支持的状态等待及 timeout，不用固定 sleep 代替就绪条件。确需跨两次调用保留弹窗、插入固定间隔或控制阶段时间窗时，再用 shell 编排。固定间隔也不保证竞态前置成立，要观察相应业务状态。

## 参数与嵌套 flow

- `runFlow` 的局部 `env` 不应假定自动向任意孙 flow 传播；跨层显式转传，或使用命令行 `-e` 共享参数。
- 静态语法正确不证明运行时参数存在。改嵌套结构后检查实际值与行为。
- 必传参数在编排层列全。历史环境中 `Number(undefined)` 生成 `NaN`，会让坐标失败而误导为产品问题。
- 文本选择器按正则全匹配考虑；界面文本包含额外字符时，明确匹配边界或使用必要的 `.*`，避免范围过宽。
- `optional: true` 允许缺失后继续，不适合作为必要步骤的成功证据。
- YAML 表达式里的 `": "` 可能被识别为键值结构，注意引用，或拆成易读的计算步骤。

## 坐标和高频操作

历史版本对 `point: "96%,6.5%"` 出现过 `NumberFormatException`；优先用整数百分比，并按当前版本验证。百分比只减少像素耦合，不能保证窗口、方向或布局变化后的目标仍相同。

`repeat` 加选择器需要反复查询层级，历史场景中未满足 1.5 秒内 10 次点击的要求。只有场景确有该时间约束、且已验证 Maestro 不满足时，才在授权内用单条设备命令循环；记录坐标与测量依据。模板不保证精确的每次点击间隔，次数和业务命中另验。

## 有界循环与滚动

不要只写 `while` 而无次数或时间上界；历史版本的默认上限很大，条件始终不满足会长时间占用设备。

```yaml
- repeat:
    while:
      notVisible: "${MENU_ITEM}"
    times: ${Number(SWIPE_MAX)}
    commands:
      - swipe: { from: { id: ".*id/second_menu" }, direction: LEFT }
- assertVisible: "${MENU_ITEM}"
```

`SWIPE_MAX` 是当前布局的上界，不是成功证明。循环结束后确认目标可见再点击，不能滑满次数仍继续。

可用当前版本支持的 `scrollUntilVisible` 代替固定次数横滑；先验证方向、目标已可见时的行为与 timeout。它减少硬编码，不自动保证跨设备、嵌套滚动或保留上次位置的页面正确。

## 弹窗、Toast 与可观察结果

历史部分弹窗使底层页面元素不再暴露，部分自定义 Toast 在 Maestro 等待和 `uiautomator dump` 中抓不到。不能推广为所有 AlertDialog、系统弹窗或 Toast 都不在层级里。

先检查当前设备的实际层级：对可定位弹窗直接操作或断言；底层不可观察时，不以底层元素缺失推断后台业务完成。短暂提示不能稳定捕获时，选择结果状态或其他明确证据，文案保留人工项。

“点击后页面未跳转”只是一项观察；需要入口就绪、点击命中、合理观察窗和业务状态证据，才能排除按钮未响应等替代原因。

## 自动化缺口

- 视觉、音质和画面观感通常仍需人工或相应专项工具；截图只是证据载体。
- 时间位置或滑块无可读值时，不能仅靠截图宣称精确数值正确。
- 失败注入需有可信构造入口；只有 host 切换不能保证指定服务端错误。
- 缺少能力时明确人工、未覆盖或无法执行，不用弱断言填成通过。
