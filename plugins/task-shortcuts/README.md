# 本地任务快捷命令

本插件用于个人 Claude Code 会话，不上传或发布。启用后注册原生 `/next`、`/changes` 和 `/commit`，由模型在任务交付前使用 prepare 工具记录工作区和推荐动作。缓存属于当前会话，不使用跨会话的全局最近目录。

- `/changes` 使用已定位的工作区，也接受显式绝对路径，通过已有 Zed 打开脚本显示项目改动。
- `/next` 消耗一次预备动作。确定性命令通过 Bash 工具原有权限检查执行；需要模型处理的任务通过延后提交提示继续。
- 新普通用户提示使待执行动作失效；查看改动不会消耗动作。没有缓存时不猜测。
- `/next` 不承载提交、推送、删除或发布。提交由独立的 `/commit` 明确授权。

本插件通过本地 marketplace 以 user scope 全局安装。新会话自动加载；已打开会话重新启动后使用。各会话预备状态独立。源目录为 ~/.claude/local-marketplace/plugins/task-shortcuts；修改源文件后更新插件版本并执行 claude plugin update task-shortcuts@personal-local。旧 next/changes 技能链接已移到 ~/.claude/backups/task-shortcuts-legacy，原文件仍在 ~/.agents/skills。不要把同名旧技能重新链接回 ~/.claude/skills，否则会阻止原生命令注册。

验证：`claude plugin test <插件路径>`。测试中的 Bash 与提示提交均为隔离模拟，不会执行真实构建、安装或打开 Zed。真实使用时确认目标窗口，手动选择 Git diff；不使用辅助功能自动按键。

## 提交入口

`/commit` 只本地提交；`/commit --push` 提交后以非强制方式推送到预先展示的唯一远端分支。prepare_commit 在所需验证完成后冻结工作区、分支、HEAD、暂存清单、提交信息、内容指纹和可选推送目标。暂存按明确文件清单逐项执行，不全量 add；无缓存时用户的 /commit 授权本次明确范围的暂存与提交。Bug 修复必须先确认编号。

调用时先通过 safe-git-submit 检查，任何预备状态变化都停止；提交仍通过该工具执行。未带 `--merge-back` 时默认分支不自动提交；冲突、未完成的 merge/rebase 操作不自动处理。推送仅支持已有远端分支且远端 HEAD 与预备 HEAD 一致，避免带出未展示的历史提交；新分支发布、其他待推提交或同步需求交给人工确认。不强推、不自动拉取或重试。提交成功但推送失败时保留本地提交，明确报告。

### 默认分支提交后合回（0.1.9）

- `/commit --merge-back`：在当前默认分支（`master`、`main` 或 `origin/HEAD` 指向的本地分支）准备，执行器创建唯一的 `commit/<原分支>-<日期>-<随机后缀>` 工作分支，提交后仅以 `--ff-only` 合回原分支。不推送，保留工作分支。
- `/commit --merge-back --push`：合回后再推送预先明确的远端目标，仍要求远端 HEAD 与准备时 HEAD 完全相同。两个参数顺序不限，不接受重复参数。
- 合回模式要求没有未暂存或未跟踪文件，不自动暂存额外内容。准备阶段不创建分支；只有本次命令的显式授权才执行。
- 提交失败保留工作分支和暂存内容；提交 hook 改变提交树、留下改动，或原分支被推进时停止，不合并、不推送、不自动回滚。合并失败同样保留现场，不改用非快进合并。
- 无缓存时仍由模型核实文件与验证后调用 `prepare_commit`，模型不提前切分支、不重复提交或合并。

验证包含隔离插件测试，以及 `node --test scripts/commit.test.mjs` 使用临时仓库与本地裸远端的真实 Git 测试；不访问真实远端，不提交用户项目。

本机 /commit 另有 ~/.claude/commands/commit.md 作为路由入口，由插件原生接管；插件未加载时按该文件的备用流程执行，`--merge-back` 仍复用同一提交执行器，不由模型另写分支合并流程。此文件属于本机全局安装的一部分。

## 缺少提交准备时

从 0.1.4 起，/commit 没有缓存时会调用模型检查工作区、范围、验证证据及提交信息，展示清单后逐项暂存并调用 prepare_commit。工具消耗本次单次授权，立即通过相同执行器提交；仅本次带 --push 时推送。无需用户输入第二次命令。有缓存时仍直接本地执行。普通 prepare_commit 调用不提交；新用户消息取消待执行授权，准备失败或执行失败不自动重试。缺失验证、Bug 编号、提交范围或推送目标时停止并说明缺口。

## 无缓存的查看与续做（0.1.6）

/changes 缺少缓存时调用模型从任务上下文定位工作区并直接打开；/next 缺少缓存时从最近明确推荐的未完成动作续做，不要求用户预备。上下文不唯一时询问，不扫描哪个 worktree 有修改来猜测。引用路径支持外层单引号或双引号。目录失效会显示实际路径，不静默改开主仓库。从 0.1.7 起仅打开正确工作区，不发送按键、不使用 AppleScript、不要求辅助功能权限；Git diff 由用户手动选择。

真实会话验证：node e2e/cli-context.mjs；SCENARIO=changes node e2e/cli-context.mjs。后者会实际打开 Zed。脚本参数验证：node --test e2e/changes.test.mjs，使用假的 zed 只核对参数，不验证 UI。
