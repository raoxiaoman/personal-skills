# 渲染审查

审查具体目标，不靠角色设定、字面匹配或统一 A/B/C 评分代替证据。可直接调用，不必先走 develop。

## 先确定范围

确认工作区、目标 diff/文件和项目规则；完整阅读目标及影响判断所需的生产者、消费者、vertex/fragment 配对、状态设置与资源释放。优先审查本次改动，不默认全仓扫描。

读取[渲染契约](../../references/render-contract.md)中的相关部分；遇关键帧/时间读取[关键帧](../../references/keyframes.md)，实际采用 GPUImage 再读取[接入参考](../../references/gpuimage-integration.md)。同一份参考共用，不循环调用 develop/shader。

## 按实际风险检查

| 范围 | 核对内容 |
|---|---|
| Shader 与纹理 | 目标版本/精度支持、vertex/fragment 接口、纹理绑定与完整性、UV 来源、坐标变换、数值边界、alpha 与 blend 因子 |
| pass 与输出 | 滤镜顺序、范围外输出、FBO/viewport/尺寸、读写依赖、反馈采样、每个必要输出是否有效，清屏与复用是否匹配契约 |
| 生命周期与线程 | GL context/线程归属、异步回调与释放竞态、缓存身份、共享资源所有权、重建与销毁路径 |
| 时间与参数 | 单位/FPS、seek/倒放、首尾/循环、间隙/冲突、当前参数是否完整求值，缓存是否改变读取时点 |
| 性能 | 实际分辨率和采样/pass 成本、CPU/分配/同步点、FBO与纹理切换、解码/上传、卡顿或内存证据 |

只覆盖相关项；不因清单存在就报告缺陷。性能建议须说明热路径、预期成本和测量或推导依据；缺少设备数据时标为待测，不宣称性能已下降。

## 反证与误报复核

- UV 越界可能是有意的镜像/重复或遮罩；先检查纹理类型、wrap 和 NPOT 支持，不直接要求 clamp。
- 中间 RGB 或 progress 超出常见范围可能是算法要求；检查消费格式、后续 pass 和范围契约，不一律裁剪。
- highp、混合公式与纹理 alpha 都取决于接口；信息缺失应标为待核实，不能把未知当已发生错误。
- GL 状态可能由外层统一管理；查清进入/退出契约再要求恢复 FBO/viewport，避免重复状态操作。纹理参数是纹理对象状态，不仅是当前绑定。
- 重复 getter 可能刻意读取新状态；证明读取时点和身份等价后才建议缓存，不按出现次数机械提取。
- 没读到生产者、调用路径或目标设备条件的推测不列为已确认缺陷。合法实现或已由调用方保证的情况应排除。

## 报告与授权

先列高置信度问题，每项包含：严重程度、`文件:行号`、具体输入/状态或设备条件、错误结果/成本、证据和最小修正方向。缺口与待测项单列，不伪装成发现，不强制为每项生成示例代码。

没有确认问题时直接说明，并列实际审查和验证范围；不写“全面安全”。只有明确授权才修复，修复后再验证。审查不授权安装、采集、提交、上传、发布或删除；临时日志遵循实际项目日志流程。
