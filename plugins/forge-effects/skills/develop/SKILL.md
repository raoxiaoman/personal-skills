# 特效开发

依据实际效果需求、工程和宿主接口工作，不预设某个应用、框架版本或固定帧率。可单独调用，不要求先走其他入口。

## 先选择最短路径

| 任务 | 读取与交付 |
|---|---|
| 只整理帧区间、曲线或参数 | 读取[关键帧](../../references/keyframes.md)，直接交付参数表或现有 API 调用；不创建完整滤镜、素材包或发布流程 |
| 组合滤镜、素材与时间范围并接入工程 | 使用下述流程和[渲染契约](../../references/render-contract.md)；确实采用 GPUImage 时再读[接入参考](../../references/gpuimage-integration.md) |
| 编写或修改 GLSL | 调用 `forge-effects:shader`；其他 Agent 可读相邻 `../shader/SKILL.md`，不重复完整开发流程 |
| 审查现有 Shader 或管线 | 调用 `forge-effects:review`；其他 Agent 可读相邻 `../review/SKILL.md`，不默认修改 |

已有任务基线和专项调查可以复用，不循环加载入口。素材命名、注册键、构建入口和打包格式以当前项目消费者为准。

## 明确效果与实际消费路径

1. 确认工作区、项目规则和现有改动，读取目标滤镜、父类、调用方与必要测试。区分需求、已有行为和未核实的历史经验。
2. 明确效果组成与顺序、输入输出尺寸和方向、alpha/混合方式、时间单位、活动范围及范围外输出。缺失信息影响结果时再问；可以安全假设的地方说明假设，不为小参数请求开启长访谈。
3. 找到纹理生产者、配置解析、Filter 消费者及预览/导出入口。多纹理、横竖方素材或共享纹理按实际路径检查，不只生成一个类就宣称接入完成。

## 选择最少的实现

- 复用已存在且语义匹配的滤镜、关键帧和素材加载机制；自定义 GLSL 只解决现有能力不足的部分，不重复实现整套框架。
- 滤镜顺序会改变结果。分别确认原图变换、lookup、视频和图片叠加的位置，不把某个旧枚举顺序当通用默认。
- 按输出契约选择末态保持、透传或其他已定义行为；不默认定格。需要输出的 pass 不能仅因范围外就跳过写入，除非调用方明确负责旁路。
- 参数按当前时间完整求值，seek、倒放、重复渲染不依赖上一次调用；循环由明确周期控制，不从最长参数轨道擅自推导。
- 纹理、FBO、素材解码器和缓存明确归属，复用与释放遵循真实生命周期。不要修改借入纹理的采样状态而不处理后续消费者。
- 热路径的采样、分配、纹理切换和中间 pass 按证据优化；不设机械行数上限，不把“少分支”或“零分配”当正确性的替代。

## 分层验证与交付

先验证参数关键边界和实际代码编译，再按风险检查 Shader 编译/链接、输入尺寸、alpha 边缘、范围外画面、seek、循环接缝与预览/导出一致性。CPU 样例、离线编译和真实 GPU/视觉验证分别报告，不能相互替代。

只准备本次需要的本地素材和配置，不自动执行加密构建中的跨仓库覆盖。上传、替换线上对象、缓存刷新、发布和删除均需独立授权；安装、启动和设备采集同样遵循当前绑定及项目流程。

交付实际代码/参数、宿主接口与必要假设、使用过的素材及来源、实际验证和未验证范围。仅在接入任务确实涉及时说明项目注册与构建步骤，不自动提交。
