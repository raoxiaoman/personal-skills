# 帧参数与关键帧

只整理参数时直接使用本流程，不创建 Filter 类、插值框架或素材包。已有 API 的构造签名、曲线归属和边界语义须从实际实现核实；名称相同不代表语义相同。

## 解析与轻量交付

把用户描述整理为“参数、帧区间、起止值、单位、曲线”。保留负号、小数、位置分量及区间顺序。未指定曲线时可明确注明按线性整理；位置先保留设计坐标，不擅自转 UV 或矩阵。

例如“曝光 0～18 帧从 0 到 2.6，18～25 帧回到 0”，可直接交付：

| 参数 | 区间 | 起值 → 终值 | 曲线 |
|---|---|---|---|
| 曝光 | 0～18 | 0 → 2.6 | 线性（未指定时的整理假设） |
| 曝光 | 18～25 | 2.6 → 0 | 线性（同上） |

这张表不需要假定 FPS；若需换秒、代码接入或范围外行为，再确认对应契约。显示值与滤镜 uniform 可能有比例或单位转换，读 setter/调用方后再换算，不能把 UI 的 70 直接当归一化强度。

## 时间域与边界

- 明确绝对时间或片段相对时间、秒/毫秒、设计 FPS 和播放/导出采样率。`frame = relativeSeconds * designFps` 保留浮点；设计 FPS 不必等于视频 FPS。
- 帧轨道长度、特效生效时长和循环周期分别确认。没有明确循环就不取模，不从最后关键帧推导整个特效周期。
- 需要循环且周期 `L > 0` 时，非负时间可取余；允许负时间时使用明确的正向归一化策略。Java/Kotlin 中 `%` 和 `*` 同优先级且左结合，`time % period * fps` 等价于 `(time % period) * fps`，加括号是为了清楚，不是修复该结合顺序。
- 明确周期区间（通常为 `[0,L)`）与精确末时刻是否属于下一轮。若要求导出最后一帧保持终值，应按产品/宿主定义处理，不能机械取模后变成首值。
- 首帧前、末帧后、间隙、同帧冲突、重叠区间分别指定保持、透传/不生效、阶跃或优先级。连续且同值的公共端点可以合并；同帧不同值不能静默去重，零长度段不能直接除以零。

## 求值与接入

线性段 `[a,b]` 内按浮点 `p = (frame-a)/(b-a)` 求 `v0+(v1-v0)*p`；仅在契约要求段内限制时 clamp。越过末关键帧后也按末态策略明确赋值，不能因找不到后一节点而沿用上次值。

每次从当前时间独立求出所需参数；对 seek、倒放、重复帧和循环重入结果一致。若历史 API 故意有状态，先理解其需求，不能未经授权改成另一种效果。

cubic-bezier 的时间进度通常对应曲线 x：应求解 `x(u)=p` 再取 `y(u)`；不能仅凭方法名假定 `getY(p)` 已完成反解。控制点附在前/后关键帧、每段曲线和超调能力均核对实现。x/y 相同的有效单调曲线表达线性时间映射，不维护没有实现依据的“必须使用某组线性控制点”禁令。

优先接入项目已有 `KeyframeTrack` 或等价能力。向量/组合属性保持分量、空间和生命周期一致；不为一段标量动画生成新的数据类、曲线枚举和全套插值器。

## 必要验证

检查首点、段中亚帧、公共端点、末点及前后、间隙/冲突、seek/倒放和循环接缝。测试预期应独立来自需求，不复刻实现；数学样例不能证明真实关键帧框架、滤镜 setter、GPU 或视觉正确。
