# 配置契约与验证边界

本文件规定工具链的核心一致性要求，不是当前 App 的完整 schema。`reference/blueprint.json` 来自旧项目，只能作为字段骨架；旧字段含义、默认值和路径必须按当前宿主源码或真实导出核对，不能从“生成成功”推导兼容。

## 输入与四组关系

生成必须提供竖屏 dump、横屏 dump，以及元数据中的 `templateNum`、`fontDir`、`stickerDir`、`fonts` 映射。宿主目录显式传入，不回退到 blueprint 中的个人设备路径。画布按方向确定；旧模板的 1075×1434、1080×610 等尺寸不是通用常量。

| 组 | 内容 | 数量要求 |
|---|---|---|
| `texts` | 竖屏文字 | `len(texts) == len(textsH)` |
| `textsH` | 横屏文字 | 与竖屏文字逐 ID 对应 |
| `stickers` | 竖屏贴纸 | `len(stickers) == len(stickersH)` |
| `stickersH` | 横屏贴纸 | 与竖屏贴纸逐 ID 对应 |

四组应存在且类型正确；文字数可以与贴纸数不同。不能把四组长度全等作为规则，也不能仅检查总数相同。

- 每个方向内，文字 `TI_13` 唯一，贴纸 `SI_11` 唯一；各自跨方向 ID 集合相同。文字 ID 与贴纸 ID 不要求互相配对。
- 按 `TI_13` 核对 `TI_1`，不能只比较文字集合；重复文案需要额外节点或人工对应证据。
- 按 `SI_11` 核对 `SI_1` 的素材文件引用与语义。不能让同一 ID 在两个方向指向不同装饰，或交换相似贴纸而仍判正确。
- 模板编号与配置中的模板归属、素材文件名、zip 名和目标目录一致。所有字体映射均须落到真实文件，所有素材引用均须可追溯。

## 生成启发式与人工确认

- **文字合并**：沿用位置与样式规则，不依赖 Figma 分组。旧规则综合字体、字号、颜色、角度差、水平重叠和垂直间距；这些条件只能提出合并候选。设计要求独立调整的多行文字应保留独立元素。
- **图形聚合**：无文字复杂组可整体作为贴纸，避免把路径拆成大量碎片。含嵌套文字的组必须递归，不能因为有图形就整体当图片。
- **尺寸背景过滤**：铺满宽度或超出画板的元素可能是背景、遮罩，也可能是有效装饰。铺满画板的容器仍需向内遍历；过滤结果必须可审阅。
- **贴纸对应**：沿用相对尺寸、名称主干和归一化位置的加权贪心匹配。横竖屏缩放不同，绝对尺寸不能直接比较。贪心结果不是语义证明，近似候选和冲突都需确认。
- **不可表达样式**：混合字体、混合颜色及无法可靠表达的效果不得静默丢弃、降级或把文字转图片；失败或转人工处理。

`conversion_report.json` 至少应让使用者追踪剔除候选及理由、合并来源、跨方向对应和待人工确认项。不能把“成功写出 JSON”或“数量一致”作为消除歧义的证据；待确认项需在交付中继续列明。

## 文字字段联动

下列关系是本工具链要检查的核心约束。嵌套的 `TI_*` 均位于 `TI_9` 内，不能误读为顶层字段。

| 字段 | 处理要求 |
|---|---|
| `TI_1` / `TI_9.TP_15` | 文字内容及内部副本相同，换行保留 |
| `TI_6` / `TI_9.TP_14` | 字体路径一致，文件名来自显式映射并有对应真实字体 |
| `TI_2` / `TI_9.TP_8` | 对当前支持的纯色文字，顶层色与填充颜色数组两项一致 |
| `TI_9.TP_2` / `TI_9.TP_7` | 分别是边框色与阴影色，不能作为填充色写入 |
| `TI_9.TI_20` / `BI_12` | 局部原始框一致，不是画布坐标 |
| `TI_9.TI_22` / `BI_13` | 目标画布几何一致 |
| `TI_9.TI_23` / `BI_10` | 主矩阵一致，不能只改一份 |
| `TI_9.TI_29` / `BI_3` | 显示缩放一致；`TI_24` 不能当作显示缩放 |
| `BI_5` / `BI_6` | 文字与贴纸均使用所属方向的画布宽高 |
| `TI_9.TI_27` / `TI_9.TI_28` | 文字布局画布与该方向画布一致 |

矩阵、坐标、尺寸和缩放出现时检查结构与有限数值，画布尺寸须为正；未出现的客户端字段不由此推定齐全。数值关系使用 `1e-7` 相对/绝对容差，不能借容差掩盖错方向或缺字段。这不是完整字段必填校验。

`TI_3` 的字号需结合宿主 sp/px 换算、字体、屏幕参数与真实 `StaticLayout` 校准；不能直接等同 Figma 字号，也没有通用的固定 2.3 倍包围盒比例。字间距、行距、换行宽度、padding、边框和阴影都会影响布局。

旋转方向、角度字段与矩阵含义按真实宿主和导出核对。当前生成器仍沿用旧宿主的文字负角候选，并保留旋转校准警告，不代表 Figma 与 Android 的坐标正角天然相反，也不能证明其他宿主正确。不能凭单张截图只改 `TI_23/BI_10`：宿主可能根据实际布局与局部框再次修正位置。

保留真实 App 导出的矩阵和画布尺寸，不为追求统一尺寸重算手调值。blueprint 中的背景、混合模式和对齐默认值也必须审阅，不能当作所有设计的正确样式。

## 贴纸、字体与资源包

`SI_1` 引用 `templateN_stickerK.png`；`SI_11` 标识横竖屏对应元素，`SI_12` 表示贴边策略，三者各有职责。编号更新以旧配置或旧包的素材语义为准，不按新目录顺序重排。

旧项目的贴边后缀约定如下，当前宿主仍需确认支持：

| 后缀 | `SI_12` | 含义 |
|---|---|---|
| 无 | 0 | 默认随比例调整 |
| `@top` / `@bottom` | 1 / 2 | 顶 / 底 |
| `@left` / `@right` | 3 / 4 | 左 / 右 |
| `@upperleft` / `@upperright` | 5 / 6 | 左上 / 右上 |
| `@lowerleft` / `@lowerright` | 7 / 8 | 左下 / 右下 |
| `@full` | 9 | 四边全贴 |

素材检查须覆盖两个方向引用的并集。字体文件名、顶层与嵌套字体引用、包内文件必须一致；贴纸文件名、编号映射与实际图片内容必须一致。不能仅检查文件存在而忽略编号互换。

zip 清单应与本次确定的配置和素材清单匹配，不允许重复条目、危险路径或混入历史文件。包内 item config 须与交付的外部配置匹配，不能残留旧配置。`cover_config_android_v2.json` 默认排除；字体按当前项目约定同时准备模板包所需文件及独立发布文件。

## 导出优先级与验证层级

完整四组 App 导出整体作为真值，不被生成器旧值覆盖。部分导出只替换显式指定方向，保留另一方向；合并后仍须满足跨方向核心关系。所有合并输出写新文件，输入保持不变。

| 验证层级 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 本地核心一致性 | 四组、ID、文字与字体副本、画布、几何联动和引用符合检查规则 | 完整 App schema、当前客户端兼容、视觉正确 |
| zip 检查 | 清单、重复文件、引用与包内配置匹配 | 图像语义配对正确、客户端下载或渲染成功 |
| 宿主与视觉验收 | 已实际验证的客户端、画布方向和操作场景符合预期 | 未执行版本、设备或场景均兼容 |
| 显式 HTTPS HEAD | 指定资源当时的 HEAD 可达性 | 资源内容一致、CDN 已刷新、客户端下载成功 |

`validate_template.py` 默认只做本地检查。`--base-url`、`--font-base-url` 是可选且显式的 HTTPS 网络检查，不允许由历史项目默认值推导目标。交付报告按实际执行层级措辞；未做宿主或视觉验收时直接说明，不写“模板已精确还原”或“已完整验证”。
