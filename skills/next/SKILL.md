# 执行推荐的下一步

从当前会话找到最近一次明确推荐、尚未完成且未因目标变化而失效的下一步。用户调用表示同意执行其中明确列出的普通开发动作组，不再重复询问相同授权。

- 先用一句话说明动作和目标工作区，随后执行，不只复述计划就结束。
- 使用当前任务明确指定的 worktree，其次根据实际操作文件确定工作区；不默认使用 session 启动目录。目标不唯一才询问。
- 完整执行推荐动作组。例如“打包 → 安装 → 启动”一次执行，不每步停下来等待 next。只推荐编译则不能顺带安装。构建失败立即停止，不安装旧包。
- 遵守目标项目 CLAUDE.md、个人开发流程和相关技能。Android 操作先使用 `forge-android:develop`（不支持插件调用时读取 `~/.agents/plugins/forge-android/skills/develop/SKILL.md`），确认实际 variant、applicationId、Gradle task 和本轮 ANDROID_SERIAL。设备未绑定或不可用时，先完成不依赖设备的已授权部分，再确认设备；不沿用历史序列号，不擅自选择设备。
- next 不授权提交、推送、删除、发布、覆盖用户数据或其他高风险动作。建议涉及这些动作时，停止并要求用户明确授权，仍遵守原有安全流程和工具权限。
- 没有明确建议、有多个互斥方案、建议已经完成或失效时，不猜测用户授权。简短说明并给出具体建议或必要问题；全部完成则明确说明，不制造新任务。
- 完成后报告真实结果和验证缺口。有必要时给出一条明确的“下一步：……”，但不自动执行新的建议。启动成功不等于功能验收通过，等待用户验证时不能代替用户判定通过。
- 查看改动等插入操作不自动取消原建议；实际目标变化、任务完成或新的明确推荐才使旧建议失效。

示例：上文建议“在 worktree A 打包、安装到绑定设备并启动”，本轮 /next → 在 A 执行完整动作组。上文仅建议“验证一下” → 明确验证范围，不据此擅自安装。
