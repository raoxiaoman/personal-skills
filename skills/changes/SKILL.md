# 查看任务工作区改动

参数：$ARGUMENTS

1. 确定目标，优先级：本次明确传入的路径；当前任务明确指定的 worktree；本次任务实际编辑文件所属的唯一工作区；尚未编辑时已明确的任务目标。只有均无信息时，才回退到 session 所在仓库。
2. 多个目标且无法唯一确定时，只询问打开哪一个。不扫描哪个 worktree 有修改来猜目标，也不以最近工具 cwd 覆盖已明确的任务工作区。
3. 执行 `bash ~/.claude/skills/changes/scripts/open-changes.sh '<目标绝对路径>'`。正确引用路径，不把参数作为代码执行。脚本验证 Git 工作区并打印根目录；失败时不改开主仓库。
4. 脚本打开对应工作区，再尝试通过 macOS 辅助功能发送 Zed 官方 Project Diff 按键 Ctrl+G、D。权限或焦点失败则提示手动按键，不循环重试、不修改权限。用户改过 Zed 快捷键时，可提示在命令面板执行 git: diff。
5. 这是该工作区全部 Git 改动的查看入口，不保证只含本会话修改。关注已暂存、未暂存和未跟踪文件，不因当前视图为空就断言整个工作区干净。
6. 不暂存、不提交、不生成补丁快照、不触发代码审查，不把查看视为验收或 next。不使用无效的 `zed --diff .`。
7. 成功仅表示打开命令及按键已发送；未经目视确认不声称 UI 已验证。简短报告，不提出新的下一步，以免覆盖原来等待 next 的建议。
